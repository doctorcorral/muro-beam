# muro-beam

A BEAM-like virtual machine for [muro](https://github.com/murolang/muro) books.

v0 (tag `v0`) is a `--safe` Agda model of that runtime: processes and mailboxes, a one-step scheduling relation, a shared heap with checked and residual grades, a total `collect`, and send that moves a grade-1 value. It imports muro's grade lattice. It does not emit code and it does not re-check a muro term.

v1a lowers a closed `GTm` that `decide run` accepts. A CEK step evaluates it on the v0 heap. Payloads are `nat`, `suc↑`, and `clo`. `collect` is one ordered pass. `lower-safe` says every reachable state stays well-formed, and a `g0` checked grade is never spent.

v1b adds `PTm`: `spawn`, `send`, `recv`, `seq`, and `done`, plus `await`, `ignore`, and `nignore`. A reply can sit in the sender's ether before it is delivered, which is the window v0's atomic `send` does not have. `no-stray-reply` says that a `PStep*` from a `ReplyDone` state leaves `mailHas` of that tag false. `ReplyDone` is what `await` and a flushing `ignore` establish on a grade-1 reply: the count of the tag in `refsOf` is zero, the object is in bounds, and `dead` is set. A naive `ignore` that demonitors without flushing does not establish `ReplyDone`, and it leaves the reply in the mailbox. The flush blanks a `suc↑` or `clo` edge that still holds the tag, so the same theorem covers a reply that lived in the heap.

v1c is the adequacy layer. `NoEscape` is the capture restriction already used by the machine: no λ is placed where a grade-1 binder is in scope. `InBoundary` implies it (`inBoundary→noEscape`) and is still only a syntactic filter. `decide-sound` is binder discharge for `decide run`. `budget-adequate` says that on every `Step*` from `lower` of a match-free `NoEscape` term, a checked grade-1 slot is spent at most once, and `exact-exhausts` says the residual is `g0` when that binder is popped. `done-collect-empty` says an empty live set frees every heap slot. `MuroBeam.Ref` is a grade-free CBV machine. Forward `lower-sim` is not a theorem: `alias` is in `NoEscape`, the reference machine β-reduces, and the CEK refuses that β because the argument is aliased. The limits are in [docs/DESIGN.md](docs/DESIGN.md).

An image is the S-expression muro writes for `--backend mbi`. Format 2 adds a `(defs …)` section of closed code; a `gref` jumps to one of those definitions. Format 3 (B4a) is the same grammar run with a host console at pid 1: `(send 1 x k)` writes, and `muro-beam` prints one line per console message before its summary line ([docs/IMAGE.md](docs/IMAGE.md#console-format-3-b4a)). The entry is a surface process term: `done`, `send`, `recv`, `spawn`, `seq`, `await`, `ignore`, and `nignore`. `(seq <btm> (done))` stays a legal entry. `load` parses that term and runs `checkP` again. The parser, the loader, and the runner are Agda ([docs/IMAGE.md](docs/IMAGE.md)). The muro emitter that writes the file is not in this repository, and it does not yet write a process term.

## Run

`make muro-beam` builds the `muro-beam` binary. Agda compiles `MuroBeam.RunImage` with `--safe` and `--ghc-dont-call-ghc`. `scripts/build_runner.py` generates `MAlonzo/RunnerMain.hs` and links it with `ghc -O0 -j1`. That main reads the path and the fuel. `loadIO`, `lowerIO`, `drive`, and the printer stay in the Agda module (`cliRun`). The main is not an Agda file, so `make audit` still sees only `--safe` modules.

```sh
make muro-beam
./muro-beam examples/images/plus.mbi
./muro-beam examples/images/suc.mbi --fuel 40
```

The default fuel is 1000, and `MuroBeam.RunImage.imgFuel` is the same number. `driveFuel` in the closed spawn proofs stays 16. The `gtyp` reply pin uses `gtypFuel`, which is 20, because that schedule is out of fuel at 16. The printed line is the outcome (`halted`, `deadlock`, `stuck <pid>`, or `fuel`), the event list, the fingerprint `h<heap>l<live>p<procs>`, and the nat `drive` kept (`v-` when it kept none). The event words are the ones in [docs/RUNTIME-BOOK.md](docs/RUNTIME-BOOK.md). `fuel` is not a finished run: it is the exit-3 case below. A pure image stops `stuck 0` with that nat. `seq1` pushes `saved` over `seg`, and `bind1` leaves that stack parked when the continuation is `done`, so a pure schedule does not reach `done`. A continuation that is not `done` is resumed. `examples/images/spawn-done.mbi` halts. `examples/images/send-recv.mbi` binds at ω, sends with `Kcopy`, halts, and keeps `v2`. `spawn-await.mbi` and `spawn-ignore.mbi` halt on the harness and on the binary, and the kept nat is `v0`. That is what `make images` and `make runner` check. `await-halted` and `ignore-halted` are `refl` pins of the hand-built terms `spawnAwait` and `spawnIgnore` at `driveFuel`. They are not a load of those files, and they do not prove the regrade, the move, or the reply. `spawn-nignore.mbi` is the same binder with `nignore`: the reply is not flushed, collect leaves index 0, and the schedule still halts (`h3l1p2 v0`). `drive-fuel` says a run that halted at `driveFuel` returns the same `Drove` at `imgFuel`. A bare `await`, `ignore`, or `nignore` under `seq` is refused (`protocol is not a spawn reply`). A protocol slot that is skipped or copied is refused (`protocol slot is not moved`). A protocol slot whose binder came from `recv` is refused (`protocol slot came from recv`): `recvStep` does not regrade the payload, so a `g1` annotation is not a move guarantee. `kind g1` is `Kmove`. `recv-move.mbi` is that file, and `recvMoveAwait-no` is the `refl`. `recvMoveIgnore-no` and `recvMoveNignore-no` are that same guard on the same term shape, for `ignore` and `nignore`. `recv-move-ignore.mbi` and `recv-move-nignore.mbi` are those files. `recv-move-shift.mbi` is a different term: it awaits the recv binder at index 1, under a later `seq`, and it has no `Kcopy` sender. `recvMoveShift-no` is the same guard on that shape. A keep that is not a protocol consumer is refused (`kept slot came from recv`), before `kind` is read, including a keep of a recv binder beside a protocol consumer of another slot. `recv-keep.mbi` is a `g1` annotation with parent `done`, and `recvKeep-no` is the `refl`. `recv-keep-copy.mbi` is an ω annotation, and `recvKeepCopy-no` is the `refl`. `recv-keep-beside.mbi` keeps the recv binder beside an `await` of another slot, and `recvKeepBeside-no` is the `refl`. `recv-keep-beside-ignore.mbi` and `recv-keep-beside-nignore.mbi` are that keep beside `ignore` and `nignore`. `recvKeepBesideIgnore-no` and `recvKeepBesideNignore-no` are those `refl`s. These pins are hand-built. They are not a load of the files, and they are not a grade theorem. `sendGate` is unchanged. This is the checker. It is not a theorem that the payload's kind matches the annotation. A further computational use of that slot, `seq (gvar 0) done` under `await 0`, is refused (`protocol slot is not one computational use`). `comp-await.mbi` is that file, and `compAwait-no` is the `refl`. A type use of that slot in the continuation is refused (`protocol slot has a type use`). `type-await.mbi` is `seq (gtyp 0) done` under `await 0`, and `typeAwait-no` is the `refl`. `markProto` still rewrites only the spawn parent root, and a protocol buried under another constructor is the same refusal. A reply `seq` whose body is not a fresh head (`gze`, `gsu`, `glam`, `gtyp`, `gpi`, or one `gref` to such a head) is refused (`reply result is not fresh`). `alias-await.mbi` is that refusal. There is no theorem from that guard to the reply tag. `bind1` refuses an aliased non-g1 cell instead of resuming it. `alias-bind.mbi` is a fresh `gsu` reply. The runner's `load` accepts the file, and the runner's `drive` promotes that cell and halts with `v1`. That is an operational result of the harness and the binary. It is not an Agda equation `load` of the file. `muro-beam --alias-bind` loads it, plants a second reference, and prints `refuse: aliased reply result` with exit 0. A load refusal under `--alias-bind` is exit 2, with `muro-beam:` and the reason on stderr, the same as a normal load. `gmatch-await.mbi`, `gvar-await.mbi`, and `gref-chain.mbi` are the other non-fresh reply bodies (`reply result is not fresh`). `glam-reply.mbi` is a direct `glam` at scope 0: no `g1` is in scope, so it loads, and `drive` keeps `v-` because the payload is a closure. `glam-g1.mbi` is that body under a grade-1 `recv` and is refused (`glam reply under g1`). `gpi-reply.mbi` is a direct `gpi` whose body is `(gsu gze)`. `evalTm` ignores that body and allocates nat zero, so the line is `v0`, not the successor. `gtyp-reply.mbi` receives one variable at `(w w)` and replies with `(gtyp 0)`. The child sends a closure, `(glam (w 0) (gsu gze))`, not a nat. `drive` keeps the first delivered nat, and a closure is not a nat, so `v0` is the cell `evalTm` allocated for `gtyp`. A child that sent `gsu gze` would keep `v1`, the received value. `glam-halted`, `gpi-halted`, and `gtyp-halted` are `refl` pins of the hand-built terms `glamReply`, `gpiReply`, and `gtypReply`. `glam` and `gpi` use `driveFuel` (16). `gtypReply` is out of fuel there and halts at `gtypFuel` (20). `await-img`, `ignore-img`, `nignore-img`, `glam-img`, `gpi-img`, and `gtyp-img` bridge those lines to `imgFuel`. `glam-img` and `gpi-img` start from `driveFuel`. `gtyp-img` starts from `gtypFuel`. They are not a load of the files. `bind-spawn-tag` still assumes the continuation `spawn (keep th)`, `isProtoAt zero pa ≡ true`, `isG1 (checked r) ≡ false` (the already-`g1` arm of `bind1` returns `just` without consulting the count), and the tail `splitGo`. `reply-hasG1` is the step from `isG1` of the returned cell to `hasG1` on that stack, and `reply-g1-count` applies `Grade1Unique`, so under `WF` that count is 1. The `*-line` pins are hand-built terms. Python `scripts/test_runner.py` is what runs the `.mbi` files. `spawn-done-line`, `bare-done-line`, `send-recv-line`, `def-spawn-line`, `gref-await-line`, and `alias-bind-line` are those pins at `driveFuel`. `spawn-done-img`, `bare-done-img`, `send-recv-img`, `def-spawn-img`, `gref-await-img`, and `alias-bind-img` equate those lines at `imgFuel`. `comp-ignore.mbi` and `comp-nignore.mbi` are the second-computational-use refusal for `ignore` and `nignore`. `type-ignore.mbi` and `type-nignore.mbi` are the type-use refusal for those two. `checkP` refuses a spawn whose parent is already tagged (`tagged spawn parent`). A tagged form anywhere else, including under `seq` as that parent, is `tagged protocol`. `tagAwait-no` is `fail "tagged protocol"` for a tag that is not a spawn parent. `spawnTagAwait-no` is a different equation, `fail "tagged spawn parent"`. `buriedTagAwait-no` is `tagged protocol` for a tag under `seq`. `sendTagAwait-no`, `recvTagAwait-no`, `spawnTagBuried-no`, `awaitUnderRecv-no`, `ignoreUnderRecv-no`, and `nignoreUnderRecv-no` pin `containsTag` under `send`, `recv`, `spawn`, `await`, `ignore`, and `nignore`. `awaitContTag-no`, `ignoreContTag-no`, and `nignoreContTag-no` are a tag in the continuation of a protocol consumer, refused by `checkP` of that continuation. Those are hand-built pins. `tagged-spawn.mbi` is an `awaitT` parent and is `not surface` at parse. `buried-awaitT.mbi` and its four siblings are the same parse refusal. There is still no theorem from `checkP` or `load` to promotion and tagging. The pure images in `VALUES` stay Python-only. `spawnAwait-alias` plants on `spawnAwait`, not on `alias-await.mbi`. `bind-count-one` derives `(count ≡ᵇ 1) ≡ true` from `bind1 ≡ just`, `isG1 ≡ false`, and the reply stack, and that bit selects the promoting arm.

| Exit | Meaning |
| --- | --- |
| 0 | `drive` finished `halted`, `deadlock`, or `stuck`. `--alias-bind` on a loaded image also exits 0 and prints `refuse: aliased reply result` |
| 1 | usage, a file that cannot be read, or a fuel argument that is not a natural |
| 2 | the file did not parse, or `load` refused it |
| 3 | `drive` returned out of fuel |

A refusal or a fuel stop also prints `muro-beam: …` on stderr. The fuel stop still prints the partial line on stdout.

`make images` is the pid-0 harness (`runFor` after one `seq1`) plus `drive` of the process images. `make runner` builds the binary and runs the file tests: format 1, format 2 with `gref`, process entries, format-3 console images, bad and truncated images, and an empty fuel. `make emit-check` asks Hex muro 0.22.13, in a private `MIX_HOME`, to emit `suc (suc 0)` and `plus 2 3`, diffs those bytes with the checked-in images, and runs the binary on the emitted files. That emitter is outside this TCB. The book pin stays muro 0.20.33. Format 2 emission is muro 0.21.22 and later, so 0.20.33 does not write a `(defs …)` section. The Agda lattice pin stays `vendor/muro` at `v0.20.32`.

## Boundary v1

`MuroBeam.Boundary` is the contract, not the implementation. The implementation is the v1a machine. The boundary re-exports it: three grades, the payloads, and the theorems a client cites (`collect-safe`, `lower-safe`, and the others named in [docs/DESIGN.md](docs/DESIGN.md)). It is versioned. This book exports boundary v1 (`boundary-version` is 1).

`BeamGrade` is `g0`, `g1`, and `ω`. An interval, including muro's `aff`, is read as `ω`: the runtime copies it and keeps the root alive. A finite point above 1 is outside those three.

`InBoundary` is a decidable check on a closed `GTm`. It refuses a closure built in the scope of a grade-1 binder. muro's `grade-once` is accepted. The additive counterexample, a `g1` variable captured in a closure and passed to an `ω` binder, is refused. That check is not a trace theorem. It implies `NoEscape`. The trace invariant for grade 1 is `budget-adequate`.

A program imports the boundary. The Muro-side spelling, once an emitter exists, is:

```
import beam "muro-beam-boundary"
def myProc : run Π (r : BeamGrade) → InBoundary r → Proc
```

That import is not a muro term in this repository. The pure Muro mirror of the boundary is the book in [`book/`](book/). It is checked with muro 0.20.33. It defines the grades, the terms, the boundary check, the runtime data, the heap operations `alloc`, `deref` / `spend`, `send`, and `reuse`, one CEK step (`eval1`, and `runFor` on fuel), total ordered `collect`, `await` / `flush` / `npeek` / `ndemon`, and the fuelled driver `drive`. It receives (`recvRoot`, and `recv1`, which parks on an empty inbox), spawns (`spawn1`, with `emit1` and `deliver1`), and schedules one `Step` or `PStep` at a time. The in-boundary `trip` runs spawn, emit a grade-1 reference, deliver, and recv, and emits `List Event`. `cex` is refused by `inBoundary` and, once lowered, `eval1` gets stuck after `runFor 6`. `MuroBeam.Event` and `MuroBeam.Emit` emit the same events. `MuroBeam.Death` is one monitor between two processes: queued mail is received first, then one `tr-down`, and the failure arm runs once. The exit step freezes that verdict. A settle after a failure exit does not clear it. A peer that is `done` or has abandoned is not a failure-arm down. A send to a peer already marked dead is consumed. `drive` is round-robin on a fuel argument. It carries a meeting list beside the system. `drive-sound` projects the `PStep*` that `drive` packages; the steps are built in `drive`, and the lemma does not rebuild them. A deadlock is `¬ At` for every pid, which is `enabled ≡ nothing`, not `¬ PStep`: `done1` still succeeds on a process that is already `pstDone`, and `emitDone1` refuses that stutter. There is no bounded-wait theorem. The conformance schedules are still the boundary trip system, and that driver chooses every pop. A `.mbi` process entry is a separate run: `loadIO`, then `drive` on `lowerIO` (a format-3 image adds the console at pid 1). `make conformance` runs both sides on `trip`, the `cex` refusal, one alloc, deref, send, eval, and collect step, the death schedules `down`, `down-again`, `down-done`, `abandon`, `send-dead`, and `settle-after-exit`, and the scheduled runs `sched-trip`, `sched-ignore`, `sched-await`, `sched-dead`, `sched-stuck`, `sched-two`, `sched-three`, `sched-down`, `sched-down-again`, `sched-up`, `sched-stray`, `sched-empty`, and `sched-console`. The event lists match. A scheduled line also prints the outcome and the nat the driver kept: the first delivered payload, or pid 0's return once parked on `saved` or an empty continuation. A `suc↑` payload counts as one more than the nat it points at (`sched-up`). `sched-stray` also prints `mailHas` of tag 0 and whether any wrapper is enabled (`en none` is `¬ At`, not `¬ PStep`). `sched-empty` prints whether the halted heap is all free. `sched-console` is a write to the B4a console at pid 1 and prints the nat of its first message. Each success line carries a fingerprint of heap length, live cells, and process count. That fingerprint is not the whole system. The plan is [docs/RUNTIME-BOOK.md](docs/RUNTIME-BOOK.md).

See [docs/DESIGN.md](docs/DESIGN.md).

## Check

Agda 2.7 or 2.8, and the standard library v2.3. The lattice is the submodule `vendor/muro`, pinned at murolang/muro tag `v0.20.32`.

```sh
git submodule update --init vendor/muro
git clone --depth 1 --branch v2.3 https://github.com/agda/agda-stdlib.git vendor/agda-stdlib
make agda
```

`make agda` checks `agda/MuroBeam.agda` with `--safe` and `--no-libraries`. `make audit` rejects `postulate`, termination pragmas, holes, and an `OPTIONS` line without `--safe`. `vendor/agda-stdlib` is gitignored.

`make conformance` checks `book/show.muro`, compiles `MuroBeam.Conform` with `agda --ghc --safe` (`+RTS -M3G -A64M -RTS`, `--ghc-dont-call-ghc`), and diffs the binary against the book printer. `scripts/conform.py` is the Haskell driver. It links with `ghc -O0 -j1`. It is not an Agda file, so the audit still sees only `--safe` modules. The command needs Agda, GHC, Elixir, and the muro 0.20.33 archive.

`make book` checks the Muro book with `mix muro.check book/smoke.muro`. `make book-show` checks the conformance printer. The archive is muro 0.20.33 from Hex, not the Agda pin above. [`docs/RUNTIME-BOOK.md`](docs/RUNTIME-BOOK.md) records both pins.
